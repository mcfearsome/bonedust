# Bonedust — Decisions

Every `[DECIDE]` from the build brief, plus structural calls that weren't specified.
Format: decision, then the reason in one line.

## Structure

- **`BonedustCore` is a local SwiftPM package, not a folder in the app target.**
  The brief requires the simulation to be pure and unit-testable. Making it a
  package means `swift test` runs the sim + economy suites on macOS in about a
  second with no simulator boot, and the compiler *enforces* purity: the package
  cannot import SpriteKit, SwiftUI, or UIKit because it declares macOS as a
  supported platform. The app target (`ios/Bonedust`) holds all rendering, input,
  audio, haptics and SwiftUI.
- **Xcode project is generated by XcodeGen from `ios/project.yml`.**
  A hand-written `.xcodeproj` is a merge-conflict machine. `project.yml` is the
  source of truth; run `make project` to regenerate.
- **Swift 6 language mode for `BonedustCore`, Swift 5 mode for the app target.**
  The core is `Sendable` value types throughout and benefits from strict checking.
  The app target is `@MainActor` SpriteKit/SwiftUI glue where strict mode only
  buys ceremony.
- **Fossil shapes are declarative *shape specs* in JSON, not raw point lists.**
  The brief asks for "a vector path in content data". A hand-authored polyline for
  a logarithmic spiral is unreadable and unmaintainable, and §6 requires porting
  the rasterizer to Ruby for the server plausibility check. So content JSON stores
  e.g. `{"kind":"spiral","turns":2.6,...}`, and a pure deterministic expander
  turns that into stroke/ellipse primitives. The Ruby port needs ~8 small
  generators instead of a bezier engine.
- **Shared constants: Swift is the source of truth, `shared/constants.json` is
  generated from it.** A `bonedust-tool dump-constants` CLI writes the JSON that
  Rails loads, and a test fails if the checked-in JSON is stale. One source, no
  drift, and no runtime JSON parsing in the hot path.

## Brief `[DECIDE]` items

- **Installment curve** — table for tiers 1–8, then ×1.32 rounded to $25:
  `350, 450, 600, 800, 1050, 1400, 1850, 2450, …`. Matches the brief's sample
  ramp and keeps tier 5 (the win-rate target) at exactly $1050.
- **Audio source: synthesized at runtime with AVAudioEngine, no sample files.**
  Brushing is filtered white noise whose band-pass centre and gain follow brush
  speed, with a different filter bank per layer (soil = low, dull; sandstone =
  bright, grainy). A crack is a short pitched-down transient; a gem is a two-partial
  bell. This is both the correct sound design for a continuous scrape (a looped
  sample audibly loops; noise does not) and zero licensing risk for a paid app.
- **Hosting: Fly.io.** One small Rails container plus one Postgres; the
  `Containerfile` is Podman-built and Fly takes an OCI image directly. Scale-to-zero
  is not wanted here (the ledger is polled), and Fly's $5 tier covers it.
- **Offline slabs count 50% toward the crew ledger.** Zero would punish playing on
  a plane, which the brief explicitly wants to support; 100% would make the
  server-seed plausibility check pointless, since a cheater would just claim to be
  offline. 50% keeps offline play meaningful and cheating unprofitable.
- **New Game Plus debt: $6,000,000.** 2.5× the original. Big enough to feel like a
  new mountain, small enough that a crew that cleared $2.4M can see the top of it.
- **Display font: SF Pro Expanded Black for now, with Rubik Dirt as a documented
  drop-in.** Rubik Dirt is OFL-1.1 so it *is* legal to bundle; I am not pulling a
  binary font into the repo without being asked. `ios/Bonedust/Resources/Fonts/README.md`
  has the drop-in steps, and `Typography.display` is the single place to switch.
  UI face is SF Pro (free, and Dynamic Type works properly); numbers are SF Mono
  with tabular figures.
- **Price: $4.99, premium, no IAP, no ads.** As briefed.

## Deliberate deviations

- **Cracks can propagate into bone that is still buried.** §3 says the crack walk
  runs "across adjacent bone cells" with no exposure condition, and `intact` counts
  all cracked cells. Keeping it literal makes the depth-1 sandstone tint tell
  (§3 Rendering) load-bearing: careful players slow down *before* they see bone.
- **`gemPay` counts fully-exposed 2×2 clusters, not `exposedGemCells / 4`.** Same
  number whenever gems are whole, and it is the behaviour the brief's "counting
  only whole gems" clause asks for; a half-dug gem pays nothing.

## Toolchain

- **This machine cannot currently run `xcodebuild` against a simulator.** Xcode 16.4
  is installed with the iOS 18.5 SDK, but the only simulator runtime present is
  iOS 26.2, which that Xcode reports as unavailable, and the attached device needs
  platform support Xcode 16.4 does not have. `xcodebuild` therefore fails with
  "Unable to find a destination matching the provided destination specifier" for
  every destination, including `generic/platform=iOS`.

  Two fixes, either is enough: install the iOS 18.x simulator runtime
  (Xcode → Settings → Platforms), or install the Xcode version that matches the
  iOS 26.2 runtime already on disk.

- **`scripts/verify-ios.sh` exists because of the above.** It drives `swiftc` against
  the iOS SDK directly to compile `BonedustCore`, the app module and the test sources,
  so a type error or an exclusivity violation is still caught in about twenty seconds
  with no simulator and no signing. It is a compile check, not a test run, and it is
  worth keeping even once the runtime is installed — it is far faster than a full
  `xcodebuild`, and it is what caught the `SlabRenderer` exclusivity bug that
  `swiftc -typecheck` alone misses, because exclusivity is diagnosed during SIL
  generation rather than type checking.

## Economy baseline, measured at M2 (2026-10-02)

`make simulate` runs 10,000 scripted runs and reports win rate per installment tier.
The M2 baseline, at Charmouth with the starting brush and **no shop purchases**:

| tier | owed | win% | §9 target | mean run $ | mean slab $ | exposure | intact |
|---|---|---|---|---|---|---|---|
| 1 | 350 | 53.1% | ~70% | 357 | 71 | 0.851 | 0.775 |
| 2 | 450 | 5.8% | ~60% | 355 | 71 | 0.851 | 0.773 |
| 3 | 600 | 0.0% | ~48% | 357 | 71 | 0.850 | 0.775 |
| 4 | 800 | 0.0% | ~38% | 356 | 71 | 0.851 | 0.774 |
| 5 | 1050 | 0.0% | ~30% | 357 | 71 | 0.850 | 0.773 |

**The economy has not been tuned against this, on purpose.** Earnings are flat across
tiers because nothing in the baseline makes the player stronger: the supply tent, the
tools beyond the starting brush, the charms and the higher-value sites are all M3 and
M4. Fitting fossil values or the installment curve to this table would mean correcting
twice — once now and once when a player who buys a fine brush on day one stops cracking
ten percent of every fossil. The tier curve gets judged after M3.

What the sweep already shows is that the core tension is real, and that is what the
balance tests lock in rather than the win rates:

| policy | exposure | intact | mean slab $ |
|---|---|---|---|
| careful (slow, long lookahead) | 0.73 | 0.87 | 63 |
| average | 0.85 | 0.78 | **71** |
| reckless (fast, no lookahead) | 0.90 | 0.36 | 47 |

Speed buys exposure and costs intact, and neither extreme beats playing between them.

Two things the simulator got wrong first, both worth keeping written down:

- **Policy speeds are cells per 60 Hz frame, not per input sample.** Using them as
  per-sample distances halved the player's speed and produced a 0% win rate at every
  tier. Any code that mixes a speed (frame-relative, like `safeSpeed` and the meter)
  with a travel distance (sample-relative) has to convert.
- **A player model with no lookahead cracks everything.** The speed EMA smooths at
  0.25, so coming down from a clearing sweep to a safe speed takes about six samples —
  a fifth of a second, by which point the brush is already over the bone. Reacting
  only to bone *under* the brush is a model of someone who has not learned the tell;
  the tell exists so you slow down before you arrive. `PlayerPolicy.lookaheadSamples`
  is the dial, and `testLookaheadIsWorthMoney` asserts that reading the slab pays.

## M2 decisions

- **Failure resets the installment tier to 1 but never touches Reputation.** The brief
  says the Collector takes your tools; it does not say what happens to the ramp. Tier
  reset makes failure cost something real, while keeping Reputation means a bad run
  cannot undo an evening's progress. Meta progression that one mistake can destroy
  makes a game hostile rather than tense.
- **All leftover cash converts to Reputation; nothing carries into the next run.**
  Straight from §4, and it is what makes a day-four purchase a gamble instead of
  deferred saving.
- **Covering the installment early does not end the run.** You always play five days.
  That is the whole point of the shop: once you are safe, the question becomes how much
  you dare spend.
- **Save data is Codable blobs inside one SwiftData row, not a model per field.**
  `RunState`, `MetaProgress` and `SlabSnapshot` are already value types that round-trip
  through JSON, nothing queries inside a saved run, and each carries a `schema` int so a
  format change is a version check instead of a SwiftData migration. Modelling
  `RunState` twice would double every future change for no gain.
- **A restored slab is refused if the bone mask no longer matches its seed.** Resuming
  a dig whose `boneCells` disagrees with the bone on screen would quietly corrupt every
  payout from then on. On refusal the day's slab is re-cut and the player is told why.
- **Navigation is a switch on a coordinator's `screen`, not a `NavigationStack`.** The
  flow is a state machine driven by `RunState.phase` and there is no "back" out of a
  slab; a push/pop stack would be a second source of truth to keep in step.
